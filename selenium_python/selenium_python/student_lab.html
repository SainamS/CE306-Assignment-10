Lab 2

กรอกฟอร์มและตรวจผล

ดูโปรแกรมกรอกข้อมูลสามแบบ แล้วตรวจว่าเว็บตอบกลับตรงกับที่ test คาดไว้หรือไม่ การเปรียบเทียบผลจริงกับผลที่คาดนี้เรียกว่า assertion

เว็บกำหนดให้กรอกชื่อ เลือกวิชา ติ๊กช่องยืนยัน และระบุหน่วยกิตเป็นจำนวนเต็มตั้งแต่ 1 ถึง 3 การลงทะเบียนในแล็บเป็นข้อมูลจำลอง ไม่มีข้อมูลส่งเข้าระบบมหาวิทยาลัย
  1. อ่านข้อมูลในตาราง แล้วคาดว่าเว็บควรตอบกลับอย่างไรในแต่ละกรณี
  2. เลือกเมนู 2 ดูข้อมูลที่โปรแกรมกรอกและข้อความที่เว็บแสดง
  3. เปิดรายงาน แล้วบันทึก expected, actual และ status ของทั้ง 3 กรณี
  4. พิจารณาว่ากรณีที่เว็บปฏิเสธข้อมูลควรทำให้ test ผ่านหรือไม่ โดยเทียบกับผลที่คาดไว้

Lab 3

รอข้อมูลด้วย explicit wait

เปรียบเทียบสองวิธี: ค้นหาข้อมูลทันทีหลังคลิก กับรอให้ข้อมูลพร้อมแล้วจึงค้นหา

เมื่อคลิก Load course information เว็บจะสร้างข้อความ COURSE_READY ใน DOM หลังประมาณ 3 วินาที กรณีแรกค้นหาทันที ส่วนกรณีที่สองใช้ explicit wait รอจนมองเห็น element โดยรอได้สูงสุด 10 วินาที

  1. จำไว้ว่าเว็บต้องใช้ประมาณ 3 วินาทีจึงแสดงข้อมูลวิชา สังเกตว่า test เริ่มค้นหาตอนไหน
  2. เลือกเมนู 3 แล้วเปรียบเทียบผลของสองกรณี
  3. ในรายงาน กรณี immediate_lookup คือค้นหาทันที ส่วน explicit_wait คือรอก่อน เปิด Screenshot เพื่อดูภาพ และ Traceback เพื่ออ่านข้อผิดพลาดของกรณีแรก
  4. ตอบข้อ 3.1 จากรายงาน ส่วนข้อ 3.2 และ 3.3 ให้คิดจากสถานการณ์สมมติ ไม่ต้องรันเพิ่ม

ผลที่ควรพบคือ EXPECTED_FAIL 1 กรณี และ PASS 1 กรณี การค้นหาทันทีจะเกิด NoSuchElementException ซึ่งโปรแกรมรายงานผ่าน EarlyLookupFailure ส่วนกรณีที่รอจะพบข้อความ COURSE_READY

กรณี immediate_lookup ถูกเตรียมไว้ให้เกิด EXPECTED_FAIL ถ้ารายงานแสดง FAIL, ERROR หรือ XPASS ให้แจ้งผู้สอน เครื่องที่ช้ามากอาจได้ XPASS เพราะข้อมูลปรากฏก่อนคำสั่งค้นหาจะทำงาน

ดูแถว immediate_lookup และ explicit_wait ในรายงาน Lab 3; เปิด Traceback ของ immediate_lookup เพื่อดูชื่อข้อผิดพลาด

  1. บันทึก Status ของทั้งสองกรณี และ Actual ของกรณี explicit_wait
  2. คัดลอกชื่อข้อผิดพลาดที่พบใน immediate_lookup เช่นชื่อที่ลงท้ายด้วย Exception หรือ Failure
  3. อธิบายว่ากรณีแรกค้นหาก่อนข้อมูลพร้อม หรือเว็บทำงานผิด โดยใช้ผลของกรณีที่รอมาช่วยอธิบาย

ข้อนี้ให้คิดจากสถานการณ์สมมติ ไม่ต้องรันเพิ่มหรือแก้โค้ด การรอคงที่คือหยุดตามเวลาที่ตั้งไว้ ส่วน explicit wait คือรอจนเงื่อนไขพร้อมภายในเวลาสูงสุด

  1. ถ้าข้อมูลเพิ่งปรากฏหลัง 5 วินาที แต่ test หยุดรอแค่ 3 วินาทีแล้วค้นหาทันที จะพบข้อมูลหรือไม่ เพราะอะไร
  2. ถ้าข้อมูลพร้อมตั้งแต่วินาทีที่ 1 แต่ test ยังหยุดรอครบ 3 วินาที จะมีเวลารอที่ไม่จำเป็นหรือไม่
  3. การรอจนข้อมูลพร้อมด้วย explicit wait ช่วยในสองสถานการณ์นี้อย่างไร

ใช้หลักการของ explicit wait ใน Lab 3 ข้อนี้เป็นสถานการณ์สมมติ ไม่ต้องจับเวลาหรือรันเพิ่ม

  1. ถ้าข้อมูลพร้อมหลัง 2 วินาที test ต้องรอจนครบ 10 วินาทีหรือทำต่อได้ก่อน อธิบาย
  2. ถ้าครบ 10 วินาทีแล้วยังไม่มีข้อมูล test จะทำต่อได้ตามปกติหรือเกิดข้อผิดพลาดจากการรอครบเวลา
Lab 4

ใช้ test เดิมตรวจเว็บสามเวอร์ชัน

ส่งข้อมูลชุดเดียวกันให้เว็บสามเวอร์ชัน แล้วดูว่าเวอร์ชันใดทำผิดกติกาและเวอร์ชันใดทำถูกต้อง

เว็บต้องรับเฉพาะจำนวนเต็ม 1-3 หน่วยกิต ทั้งสามรอบใช้ test เดียวกัน ส่งค่า 4 และคาดว่าเว็บจะตอบ CREDITS_OUT_OF_RANGE

  1. เขียนผลที่เว็บควรตอบเมื่อรับค่า 4 หน่วยกิต โดยยึดข้อกำหนดข้างต้น
  2. เลือกเมนู 4 สังเกต version บนหน้าเว็บ ซึ่งจะเปลี่ยนจาก buggy เป็น fixed แล้วเป็น refactored
  3. เปิดรายงานเพื่อเทียบ expected กับ actual ของทั้งสามรอบ และอ่าน traceback ของ buggy
  4. ใช้ผลที่พบอธิบายว่าแต่ละรอบตรงกับขั้น Red, Green หรือ Refactor อย่างไร
เวอร์ชันการเปลี่ยนที่เตรียมไว้
buggy / Redเวอร์ชันที่มีบั๊ก คือทำงานผิดกติกาเรื่องหน่วยกิต
fixed / Greenเวอร์ชันที่แก้กติกาการตรวจหน่วยกิตแล้ว
refactoredเวอร์ชันที่จัดโครงสร้างโค้ดใหม่ โดยตั้งใจให้ทำงานเหมือน fixed

แล็บนี้ควรได้ EXPECTED_FAIL 1 กรณี และ PASS 2 กรณี

แล็บนี้ใช้เว็บสามเวอร์ชันที่เตรียมไว้ เพื่อให้เห็นผลของ Red-Green-Refactor การฝึก TDD ให้ครบกระบวนการยังต้องลงมือเขียน test และแก้โปรแกรมด้วยตนเอง

ดูสามแถวในรายงาน Lab 4: credits_4_buggy, credits_4_fixed และ credits_4_refactored ทุกแถวส่งค่า 4 เหมือนกัน

  1. คัดลอก Expected, Actual และ Status ของทั้งสามเวอร์ชัน
  2. ระบุว่าเวอร์ชันใดทำผิดกติกา และทำผิดอย่างไร โดยอ้าง Actual ของเวอร์ชันนั้น

เทียบ Actual ของ fixed กับ refactored ในรายงาน Lab 4; refactored คือเวอร์ชันที่จัดโครงสร้างโค้ดใหม่

  1. บอกว่าผลของ fixed และ refactored เหมือนหรือต่างกันอย่างไรเมื่อรับค่า 4
  2. Lab 4 ลองเฉพาะค่า 4 เรายืนยันได้หรือยังว่าเวอร์ชัน refactored รับค่า 1 และ 3 ได้ถูกต้อง เพราะอะไร
